# 오이붕 갤러리

친구들이 만든 게임을 모아 놓은 사이트. 메인 화면의 **작품 전시 / 평가·후기** 탭에서 게임과 플레이어 후기를 따로 볼 수 있다. 게임 상세에서는 스크린샷을 관리하고, 후기 탭에서 게임을 선택해 별점·글(최대 2,000자)·사진(최대 3장)을 남긴다. 기존 후기들은 삭제하지 않고 같은 피드에 표시된다. 후기는 게임당 브라우저 하나에 한 건이며 다시 저장하면 글·별점·사진을 수정할 수 있다.

## 게임 등록과 평가

사이트 하단의 **게임 등록하기**에서 게임을 등록한다. APK나 마인크래프트 모드처럼 웹 플레이 주소가 없는 게임은 링크를 비워 둔다. 등록한 게임이나 기존 게임의 **게임 자세히 보기**에서 스크린샷을 올릴 수 있다. **평가·후기** 탭에서 모든 게임의 후기를 모아 보고 게임별 필터로 확인할 수 있으며, **후기 작성하기**에서 닉네임·별점·글과 JPG/PNG/WebP 사진(장당 5MB, 최대 3장)을 올린다. 등록 화면에서 개발자 이름, 개발 상태(미정 / 개발 중 / 정식 출시 / 라이브 서비스 / 완결), 썸네일을 지정할 수 있다. 목록 상단의 상태 필터에서 라이브 서비스 중인 게임을 따로 볼 수 있다. 게임 등록·수정에서 **소개 배경색**을 선택하면 작품 카드와 상세 화면의 소개 영역에 적용된다. 썸네일은 JPG·PNG·WebP로 최대 5MB다. 누구나 게임 카드나 상세 화면의 연필 버튼으로 게임 정보를 수정할 수 있다. 같은 브라우저에서 저장한 평가는 **내 평가 수정**에서 수정한다. 브라우저의 사이트 데이터를 지우면 이전에 남긴 평가와의 연결이 사라진다. 모든 방문자는 상세 화면에서 각 스크린샷 아래의 **삭제** 버튼을 누르고 확인하면 해당 사진을 삭제할 수 있다. 스크린샷은 JPG·PNG·WebP로 파일당 5MB까지 올릴 수 있다. 공개 글에는 등록 한도가 적용된다.

## 전시관 편의 기능

- 상단의 대표 전시는 등록된 모든 작품을 후기 점수·후기 수 기준의 전시 순서로 순환합니다. 약 6.5초마다 자동으로 다음 작품으로 이동하며 마지막 작품 다음에는 처음으로 돌아갑니다. 이전·다음 버튼으로 직접 넘길 수도 있습니다. 마우스로 가리키거나 키보드로 조작하는 동안, 상세 창을 열거나 다른 탭을 보는 동안에는 자동 전환하지 않습니다. 시스템에서 동작 감소를 설정하면 자동 전환은 비활성화됩니다. 임의의 실제 순위나 방문자 수는 표시하지 않습니다.
- 작품 카드를 누르면 상세 소개가 열립니다. 외부 게임 실행은 별도 플레이 버튼을 사용합니다.
- 검색·개발 상태 필터와 정렬(기본/최신/제목/평점/후기 수), 찜 목록 및 같은 브라우저의 최근 감상 작품을 사용할 수 있습니다. 평점이 없는 게임은 평점순 정렬에서 뒤로 갑니다.
- 상세 화면의 **공유**를 누르면 해당 작품이 바로 열리는 `?game=<작품ID>` 링크가 복사됩니다.
- 스크린샷과 후기 사진을 누르면 새 탭 대신 사진 감상 창이 열리고 좌우 버튼 및 화살표 키로 넘길 수 있습니다.
- 후기 작성창에서 사진 미리보기와 개별 첨부 취소, 글자 수 표시, 별점 선택, 미저장 변경 사항 닫기 경고를 지원합니다.
- 게임 상세에서 작품 소식(제목·내용)을 게시할 수 있습니다. `수정 기록 보기`는 **적용 이후** 수정된 텍스트/상태/링크만 기록합니다. 복원은 이전 내용을 수정창에 채운 뒤 사용자가 저장하는 방식이며 이전 썸네일·스크린샷까지 복구하지는 않습니다.
- 작품 정보 신고는 서버에 비공개로 적재됩니다. 신고 내용을 처리할 관리 UI는 별도로 제공하지 않으므로 Supabase 관리자에서 확인해야 합니다.
- 작품별 평점/후기 수는 기존 `oc_reviews`의 실제 데이터에서 계산하며 평가를 삭제하거나 초기화하지 않습니다.

## 작품별 추가 정보

게임 등록·수정 화면의 **추가 정보 (선택)**에서 플랫폼(웹/PC/Android/게임 모드/기타)과 싱글·멀티 플레이 여부를 지정할 수 있습니다. 메인 카드에는 추가 정보를 과도하게 표시하지 않고 작품 상세에만 작은 라벨로 표시합니다. `20261112100000_platform_play_modes.sql`이 해당 열과 수정 이력 트리거를 확장합니다.

## 추가 데이터베이스 설정

`20261112090000_exhibition_curation.sql`은 `oc_game_revisions`, `oc_game_updates`, `oc_content_reports`를 생성합니다. 수정 기록 테이블에는 공개 조회만 허용하고 쓰기는 서버 측 트리거가 담당합니다. 소식과 신고는 `oibung-guest` Edge Function을 통해서만 저장합니다. 신고 테이블은 일반 사용자에게 조회 권한을 주지 않습니다.

## Supabase 연결

`supabase/migrations`의 SQL을 순서대로 적용하고 `oibung-guest` Edge Function을 배포한다. 이 함수는 공개 방문자 요청을 받으며 게스트 키, 입력값, 등록 한도를 자체 검증한다. 허용된 출처는 함수의 `origin`에 설정한다.

```sh
supabase functions deploy oibung-guest --no-verify-jwt
```

`community-config.js`에는 프로젝트 URL과 브라우저용 Publishable key를 입력한다. 서비스 역할 키는 Edge Function 런타임에서만 사용한다.

## GitHub Pages 배포

1. GitHub에 `oibung-corporation` 저장소를 만들고 이 폴더의 파일을 저장소 최상단에 커밋한다.
2. 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch → main → /(root)**를 선택한다.
3. Pages에 표시된 배포 주소를 두 개의 브라우저 세션에서 연다. 게임을 등록하고, 상세에 이미지와 평가를 추가한다. 다른 창에서 새로고침 없이 반영되는지 확인한다. 같은 게임에서 평가를 다시 저장하고 평가 수가 그대로인지 확인한다.

## 로컬 실행

```sh
python3 -m http.server 8000
```

`http://localhost:8000`에서 연다. Supabase 설정 전에도 초기 게임 목록과 검색, 찜을 확인할 수 있다. 찜은 브라우저에 저장된다.
