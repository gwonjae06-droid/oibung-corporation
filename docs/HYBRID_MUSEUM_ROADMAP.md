## 0. 최종적으로 만들 경험

- **일반 모드:** 실제 유럽 궁전·미술관 같은 신고전주의 건축, 따뜻한 조명, 대리석, 황금 액자. 정돈된 시각 구성.
- **소등 모드:** 동일한 건축과 작품 위치를 유지하되 완전 소등, 약한 붉은 비상등, 손전등, 절제된 불안감과 환경음.
- **탐험:** Ren'Py식 정해진 카메라 구도에 따라 정문 → 로비 → 회랑/특별 전시실 → 작품 근접 감상 → 상세 페이지로 자연스럽게 이동. 자유 카메라와 졸라맨은 없음.
- **선명도:** 배경은 미리 렌더한 3D 이미지, 작품과 비서는 별도 2D 레이어, 글씨는 HTML 텍스트. 모바일에서도 글씨가 흐리지 않아야 함.
- **기능 보존:** 등록 게임, 개발 상태, 수정, 스크린샷, 후기, 평점, 플레이 링크, Supabase 데이터 및 권한 관련 기능의 정상 동작.

## 2. 다음 작업 — 실행 순서와 완료 기준

### P0 — 안정성, 읽기 쉬운 UI, 실제 동작 확인 (배포 전 필수)

- [ ] **모바일 화면 실기기 검사:** iOS Safari / Android Chrome의 세로·가로 모드에서 장면 이동, 뒤로, 소등, 손전등, 작품 클릭, 비서 숨김, 지도, 다이얼로그가 실제로 잘 작동하는지 확인.
- [ ] **모든 화면 요소 충돌 확인:** 헤더·전시 탭·게임 등록 버튼·필터·지도·비서·액자 명패·방향 버튼의 클릭 영역과 겹침을 작은 화면/가로 모드까지 검토. 높이 320~430px 가로 화면도 검사.
- [ ] **작품 접근성 검증:** 작품이 0/1/3/10/30개일 때 입구, 로비, 각 회랑, 특별 전시실, 지도 접근 및 각 작품 상세가 막히지 않는지 검증. 검색·정렬·즐겨찾기 필터 적용 시 작품 선택 일관성도 확인.
- [ ] **네트워크 오류 내성:** 느린 이미지 요청, 잘못된 썸네일, AVIF 미지원/로드 오류, Supabase 지연·연결 실패, 이미지 교체 중 이동 시 검은 화면·JS 예외·무한 로딩 없는지 확인.
- [ ] **기존 데이터 회귀 검사:** 게임 등록/수정, 공개 수정 권한 정책, 개발 상태, 링크 없는 게임, 사진 업로드·삭제, 평점·후기·사진, 신고, 저장 후 실시간 UI 갱신을 실서버 테스트 계정/테스트 데이터로 검증. 기존 사용자 데이터 임의 삭제 금지.
- [ ] **접근성:** 키보드 초점 표시, Enter/Escape 동작, 대화상자 닫힘 후 초점 복귀, 스크린리더 안내, 터치 타깃 44px 내외, 모션 감소/사운드 기본 꺼짐 적용.
- [ ] **성능 수치 측정:** 중저가 Android와 일반 데스크톱에서 LCP, CLS, 메모리, 전환 지연, 최초 다운로드 총량을 측정하고 목표 미달 시 이미지 로딩 전략·합성 레이어를 조정.
- **완료 기준:** 주요 사용자 흐름의 자동 및 실제 기기 수동 테스트 통과. 클릭 불가 버튼, 검게 비는 작품, 수평 오버플로, 재현 가능한 치명적 오류 0건.

### P1 — 건축 모델링·배경의 '실사형' 품질 높이기 (가장 중요한 시각 작업)

- [ ] **Blender 건축 품질:** 반복 구조의 밋밋함 제거. 고품질 대리석·석재·목재·금속 재질, 현실적인 거칠기·반사·접촉 그림자, 몰딩·기둥·천장 조각·조명기구 세부 모델링.
- [ ] **공간 구분감:** 입구, 중앙 로비, 좌측·우측 회랑, 특별 전시실이 실제로 연결된 건물로 느껴지되 카메라·화각·방향 관계가 일관되게 유지되도록 장면 구성 재설계.
- [ ] **장면별 액자 정합성:** Blender 렌더에서는 액자 중앙을 빈 영역으로 남기고 실제 DOM 작품 썸네일과 크기·위치·원근·그림자·조명을 맞춤. 작품명·개발자명은 HTML 유지.
- [ ] **라이트 리깅:** 낮은 미술관 스포트 조명·창문/천장 채광과, 소등 시 완전히 사라지는 메인 조명 및 비상등을 분리. 낮/밤 카메라와 건물 구조를 픽셀 단위로 동일 유지.
- [ ] **모바일 별도 구도:** 단순 가운데 크롭이 아닌 세로 화면 전용 렌더 조정. 액자, 복도, 비서, UI가 한 화면에 균형 있게 들어오도록 설계.
- [ ] **과도한 블러 방지:** 렌더 자산 선명도 평가, 이미지 적절한 크기/압축률, 미세 텍스처 계단 현상·부족한 해상도 검사.
- **완료 기준:** PC/모바일 6개 장면 × 낮/밤을 실제 스크린샷으로 비교해 실사풍의 재질·조명·구도 및 액자 정합성을 확인. 참고 이미지를 복제하지 않고 고유한 디자인을 유지.

### P2 — 안내 비서의 Live2D풍 표현 및 게임별 의상

- [ ] **고해상도 2D 비서 자산 통일:** 원본 비율과 색감, 선명도, 얼굴 비례가 의상별로 일관되도록 정리.
- [ ] **표정·동작 분리:** 눈 깜빡임, 시선, 호흡, 고개 움직임, 입모양·손/의상 소규모 움직임. 표정/동작 프레임은 게임 별로 재사용 가능한 구조.
- [ ] **작품별 의상:** 오든링 대검 기사, 퍼리Corp 고양이 귀 메이드, 오이붕 아레나 전투 안내복을 우선. 기타 게임은 기본 비서 의상으로 자연스럽게 폴백.
- [ ] **안내 맥락:** 작품 전환/접근/상세 열기/소등에 맞춘 짧은 반응. 길고 반복적인 설명, 자동으로 텍스트를 가리는 말풍선, 과도한 UI는 피함.
- [ ] **모바일 배치:** 작품·명패·방향 버튼을 가리지 않도록 축소/위치 변경/숨김 상태 유지.
- **완료 기준:** 의상 변경 시 화면 흔들림이나 이미지 늘어남이 없고, 감상·조작을 방해하지 않는 부드러운 2D 움직임. **정식 Live2D Cubism과 동등한 리깅인지 여부는 별도 명시.**

### P3 — 소등·공포 모드의 완성도

- [ ] **정전 시퀀스:** 짧은 1~2회 조명 불안정 → 소등 → 비상등 → 손전등. 모션 감소 또는 번쩍임 설정 OFF면 깜빡임 생략.
- [ ] **손전등 연출:** 부드러운 경계·휘도 조정, 비춘 작품의 정확한 가시성, 모바일 터치 방향 제어. 다크모드에서도 필수 버튼·이동 경로는 항상 읽을 수 있음.
- [ ] **불안한 분위기:** 드문 그림자·복도 끝 현상·비서 침묵 등을 낮은 빈도로 배치. 갑툭튀·강제 화면 흔들림 반복 금지.
- [ ] **환경음 제작:** 낮은 기계음, 발소리 잔향, 드문 문·금속 소리의 공간감. 사운드는 기본 OFF 또는 사용자 선택이며 개별 볼륨/끄기 지원.
- [ ] **오디오/화면 접근성:** 갑작스런 큰 소리 방지, 모션 감소 옵션 존중, 광과민 주의 및 대비 점검.
- **완료 기준:** 동일 작품·동일 동선이 두 모드에서 유지되고, 소등을 켜도 작품 선택과 상세 페이지 접근이 불가능해지지 않음.

## 3. 다음 개발에서 지켜야 할 원칙

1. **건축 배경은 Blender에서 제작해 사전 렌더**, 웹에서는 정적 장면 표시. 필요하지 않은 실시간 3D/WebGL·자유 카메라·점프·졸라맨으로 되돌리지 않기.
2. **작품과 비서는 독립된 2D 고해상도 레이어**, 작품명·제작자명·버튼은 HTML 텍스트. 정보 표시를 배경에 굽지 않기.
3. **모바일 우선:** 비서와 UI가 작품을 가리지 않고, 작은 화면에서 모든 버튼을 실제로 누를 수 있어야 함.
4. **새 게임 수에 자동 대응:** 지정된 4개 기본 게임만 정상 작동하는 하드코딩 금지.
5. **기존 커뮤니티 데이터 보존:** 등록, 후기, 사진, 링크, 기존 사용자의 수정 정보 손실 금지.
6. **불필요한 텍스트·버튼 제거:** 화면에서 작품·공간·비서·이동이 중심. 설정·후기·정보는 상세 화면에 배치.
7. **공포는 분위기 중심:** 소등은 단순 검정 테마가 아니며, 소리·빛·비서 반응이 달라져야 한다. 접근성 설정 보장.
8. **완료 판정에 근거 남기기:** 코드 적용 / 자동 테스트 통과 / 실제 기기 검수 / 배포 완료를 서로 구분해 기록.
