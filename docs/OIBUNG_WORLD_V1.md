# 오이붕 월드 — 2D 도트 횡스크롤 게임 소개 웹사이트

## 목적

**친구들이 만든 게임이 각각 거대한 건물로 존재하는 하나의 도트 세계**를 돌아다니며 작품을 발견하고 소개받는 사이트. 전투나 퓨즈 수집, 스토리 강제진행 없이 **게임을 소개하고 플레이하는 것**이 목적이다.

## 구현 구조

- 렌더링: `oibung-world.js`, 단일 Canvas 2D, 저해상도 내부 캔버스와 `image-rendering: pixelated` 확대. 배경·지면·하늘·건물·가로등·분수·플레이어·안내 비서를 픽셀 도형으로 구성. Three.js, WebGL, 외부 그래픽 API 없음.
- 월드 동선: 시작 광장 → 게임별 대형 건물들이 횡으로 배치됨. 좌/우 카메라 추적 및 패럴랙스 배경. 스페이스/위쪽 방향키 점프.
- 키보드: **A/D 또는 좌/우** 이동, **E/Enter** 입장, **Space/W/위 방향키** 점프.
- 모바일: 왼쪽·오른쪽·점프·건물 입장 버튼. 길게 누르는 이동과 스와이프/스크롤 충돌 방지.
- 안내 비서: 검은 머리와 조끼, 버건디 넥타이를 가진 2D 도트 NPC가 플레이어 뒤를 따라 걷고, 건물 근처에서는 게임별 소개 멘트를 표시.
- 작품 건물: 오든링(고딕 성), 오이붕 아레나(콜로세움), 오이챔스(검격 도장), 대학전선(전략 지휘 본부), 퍼리 관련 작품(고양이 저택). 일반 신규 작품에는 제목과 장르에 따라 스튜디오·탑·경기장·저택 템플릿을 적용.
- 입장: 건물 근처에서 **E** 또는 **건물 들어가기**를 누르면 기존 `window.OIBUNG_CATALOG.openDetail(game.id)`를 호출. 기존 게임 소개·스크린샷·후기·플레이 링크·GitHub·수정 UI를 재사용.
- 빠른 작품 탐색: 모든 건물의 이동 셀렉트와 건물 목록. 이름을 누르면 해당 건물 입구로 순간 이동.
- 목록 보기: 사용자가 직접 원하는 게임을 빠르게 찾을 수 있도록 예전의 게임 카드 검색·정렬·찜 목록은 접힌 `전체 게임 카드로 보기` 메뉴로 보존.
- 게임 추가: Supabase를 통해 `saveSharedGame` 또는 `setSharedGames`가 호출되면 `oibung-catalog-updated` 이벤트를 통해 월드에 건물을 자동 생성·업데이트. 서버 데이터 변경 없음.

## 파일

| 파일 | 용도 |
|---|---|
| `oibung-world.js` | 도트 월드 엔진, 플레이어·NPC·카메라·입장·테마 자동 배치 |
| `oibung-world.css` | 도트 게임 UI와 모바일/가로화면 조작 |
| `index.html` | 월드 스테이지와 조작기·빠른 이동·목록 DOM |
| `app.js` | 새/수정 게임이 등장하면 월드 갱신 이벤트 방출 |
| `tests/oibung-world.cjs` | PC/휴대전화 세로/가로에서 실제 키보드·동선·입장·자동 생성·후기 검증 |
| `.github/workflows/oibung-world.yml` | Chromium 자동화와 화면 스크린샷 |

## 보존과 제한

- 기존 Supabase 등록·수정·후기·사진·플레이 데이터는 건드리지 않는다.
- 기존 다크모드 선택, 후기 게시판, 게임 등록과 URL 공유 기능은 유지.
- `games.js`의 기본 게임이 있으면 즉시 표시, 공유 데이터가 로드되면 다시 갱신.
- 처음 버전의 건물 그래픽은 모두 **코드로 직접 그리는 절차형 픽셀아트**이며, 각 작품의 실제 전용 손그림 2D 스프라이트와 게임 BGM/효과음은 앞으로 교체 가능한 미술 개선 대상. 기본 제공 게임을 넘어 작품별 일러스트의 수작업 퀄리티를 무리하게 주장하지 않는다.
- 월드의 그래픽은 도트화하지만, 작품 자체의 등록 스크린샷과 HTML 설명은 원본·선명한 상태를 유지. 작품 자료를 강제로 픽셀화하지 않아 정확한 소개 가능.
- 모바일 실제 기기 및 Supabase 쓰기 시나리오는 배포 전 브라우저 자동 테스트와 별개이다.

## 검증 목표

1. 게임별 건물이 각자 다르게 보여야 하고, 입구 E/탭으로 기존 작품 상세가 열려야 한다.
2. PC의 키보드·모바일 이동 버튼을 실제로 눌러 이동할 수 있어야 한다.
3. 세계에 존재하는 모든 게임이 빠른 이동 목록에 나타나야 하고, 새 게임 추가 시 즉시 건물이 생겨야 한다.
4. 기존 상세·등록·수정·후기 UI가 없어지거나 데이터가 유실되지 않아야 한다.
5. 1440×900, 390×844, 844×390에서 UI 버튼이 잘리지 않으며 가로 스크롤이 발생하지 않아야 한다.
