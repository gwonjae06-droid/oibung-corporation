# OIBUNG GALLERY — 하이브리드 전시관 v1.1 구현 및 QA 기록

## 현재 구현 상태

**이 브랜치에는 실제 Blender가 출력한 배경 AVIF 이미지 24장이 포함되어 있습니다.** 초기 CSS 전시관 목업에서 한 단계 진행된 버전이며, Unity/Three.js 실시간 자유이동은 실행하지 않습니다.

- 정문 → 중앙 로비 → 좌우 회랑·특별 전시실 → 작품 정면 → 근접 감상 → 기존 작품 상세 페이지
- 실시간 등록 카탈로그의 썸네일(또는 대체 포스터), 작품명, 제작자명, 리뷰·수정·스크린샷·플레이 링크와 연결
- PC 방향키 / Enter / E / M / F, 터치 버튼, 터치 스와이프, 뒤로 이동 스택
- 2D 비서의 테마 의상(오든링 기사·퍼리Corp 메이드·아레나 전투복 등), 가벼운 호흡 움직임 및 숨김
- 낮·소등 모드 간 동일 카메라를 사용하는 이미지 교체. 비상등과 손전등은 레이어로 처리하고, 손전등 안에서는 동일 구도의 낮 배경을 부드럽게 복원
- 환경음은 기본 꺼짐이고 개별적으로 켤 수 있음. 깜빡임도 별도로 해제 가능
- 정적 배경 1장과 1~3개 액자만 표시하고 GPU의 연속 프레임 렌더링을 하지 않음

## Blender 원본 배경 24장

모델 생성: `tools/render_museum.py`. GitHub Actions 워크플로: `.github/workflows/render-museum.yml`.

| 시점 | 형태 | 낮 | 소등 | 파일 |
|---|---|---|---|---|
| entrance | 대칭 정문 | ✓ | ✓ | `assets/museum/entrance-{light,dark}*.avif` |
| lobby | 중앙 로비 | ✓ | ✓ | `assets/museum/lobby-{light,dark}*.avif` |
| left | 좌측 회랑 | ✓ | ✓ | `assets/museum/left-{light,dark}*.avif` |
| right | 우측 회랑 | ✓ | ✓ | `assets/museum/right-{light,dark}*.avif` |
| special | 특별 전시실 | ✓ | ✓ | `assets/museum/special-{light,dark}*.avif` |
| focus | 작품 근접 | ✓ | ✓ | `assets/museum/focus-{light,dark}*.avif` |

각 장면은 데스크톱 **1600×900** 및 모바일 **720×1280** 전용 렌더를 보유하므로 6×2×2=24장. `gallery-scene-assets.js`가 파일 경로를 등록하며, 장면 이미지가 사라지거나 전송 실패하면 CSS 건축 배경으로 돌아갑니다. 배경에는 작품 정보, 그림, 비서를 그리지 않고 HTML/CSS 이미지·글씨 레이어에서 독립적으로 합성합니다.

모델은 대리석 바닥, 금빛 몰딩, 기둥, 아치형 출입구, 천장 구조, 샹들리에, 벽 조명 등 절제된 신고전주의 건축입니다. Blender가 실제 렌더한 3D 공간이지만, 참고 이미지와 동등한 **극사실적 건축 자산이라고 간주하면 안 됩니다**. 세부 텍스처, 독특한 소품, 손전등에 맞춘 정밀 광량 시뮬레이션은 추가 아트디렉션 대상입니다.

## 검증 방법

정적 사이트를 로컬 HTTP 서버에서 열고 `tests/museum.smoke.cjs`의 Playwright 테스트를 실행합니다. GitHub Actions `.github/workflows/museum-smoke.yml`은 변경 시 다음 세 화면을 검사하고 스크린샷을 보관합니다.

- 데스크톱 1440×900
- 모바일 세로 390×844
- 모바일 가로 844×390

검증 항목: 장면 생성, 화면 표시, 로비/회랑 이동, 전시 지도, 작품 상세 대화상자, 소등·손전등 전환, 가로 스크롤 넘침, 주요 JavaScript 오류. **실제 PC·안드로이드/iOS 기기에서의 FPS와 배터리 소모 수치는 측정하지 않았습니다.**

## 보존한 데이터/기능

기존 `app.js`, `community.js`의 등록·수정·후기·사진·상세·공유 기능과 Supabase 테이블·데이터를 직접 변경하지 않았습니다. 기존 DOM 카탈로그는 보존되고 새 장면 엔진이 이를 읽습니다. 단, 모든 Supabase 권한·네트워크 변형 시나리오를 종단 간 테스트한 것은 아닙니다.
